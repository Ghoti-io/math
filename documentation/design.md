# Design

**Status:** `sin`, `cos`, `tan`, `atan2`, `exp`, `log`, `pow` and `hypot` are implemented (CAP-1).

Deterministic elementary functions that give the same bits on every host.

The dependency rules and the determinism gates that bind this library are in
the Makefile's header comment and in `tools/`: `check-fp-contract`,
`check-edges`, `check-libm` and `check-no-x87`, each shown to fail on a planted
violation by `make check-gates`. The plan is in the workspace, not in this
repository.

## sin, cos and tan

Written from published algorithms and the oracle's results only; no library's
source was read.

**Reduction.** For `|x| > pi/4`, `x * 2/pi` is formed exactly enough by the
Payne-Hanek method (Payne and Hanek, 1983): the integer-valued bits of `2/pi`
beyond the window that can matter are multiples of 4 and dropped; a 256-bit
window of the bits below is multiplied by `x`'s 53-bit significand in 32-bit
limbs with 64-bit products. That gives the quadrant (`N mod 4`, with the
fraction rounded to the nearest integer) and a 256-bit fraction in `[-1/2, 1/2]`,
whose leading 106 bits times `pi/2` (a double-double) give `r = rh + rl`,
`|r| <= pi/4`, to a relative error of about `2^-100`. The smallest fraction any
double has is about `2^-61` (`6381956970095103 * 2^797`), so the window's
truncation error of `2^-168` is far below one ulp of the result. Only integer
arithmetic is used: a 128-bit type is not available on i686 and an integer to
double conversion compiles to an x87 `fild` there, which `check-no-x87` refuses,
so a 53-bit integer becomes a double through the bit pattern of `2^52 + k`.
The table is indexed from the exponent of `x`, so `|x|` up to `DBL_MAX` takes
the same code as `|x| = 1`.

**Fast reduction.** For `pi/4 < |x| < 2^20` the quotient is one multiplication
(`n = round(x * 2/pi)`, taken through the `2^52 + 2^51` trick, which needs no
integer to double conversion) and the remainder is `x - n*P1 - n*P2 - n*P3 -
n*P4` with `pi/2 = P1 + P2 + P3 + P4`, `P1..P3` of 33 bits and `P4` a double
(Cody and Waite, 1980). Every product with `P1..P3` is exact because `n` has at
most 20 bits, `x - n*P1` is exact, and the sums are Knuth's TwoSum, so the
remainder is a double-double accurate to `2^-134` absolute. That is
`2^-79` of the remainder or better for `|r| >= 2^-55`, and the fast path hands
anything smaller (no double below `2^20` is closer than `2^-60` to a multiple
of `pi/2`) to Payne-Hanek, as it does a quotient the rounding put one off
(`|r|` above the double `pi/4`). Where it answers it returns the same `n` and
the same `rh` as Payne-Hanek and an `rl` that differs by under `2^-79 |r|`
(measured at most `2^-87`), so the results are the same bits: the committed
hash over the original 46,569 results did not change. `trig.c` states the
proof, `test_trig_reduce.cpp` compares the two reductions, and `make bench`
times them.

**Kernel.** A table-driven kernel (Tang, 1991; Muller, Elementary Functions,
chapters 4 and 5) for the reduced argument `h + l`, `0 <= h <= pi/4`. Write
`h = a + b` with `a` the leading six bits of `h`'s mantissa (64 slices per
binade for `2^-4 <= h < 1`, so 256 values of `a` and `0 <= b < a/64`). Row `k`
of a 257-row, 64-byte-row table (16 KB, `src/elementary/trig_kernel_table.h`)
holds `sin a` and `cos a` as double-doubles, `tan a` and `cot a` as doubles,
and the exact residuals `d0 = sin_hi - tan_hi cos_hi` and
`e0 = cos_hi - cot_hi sin_hi`; the last row is `a = 0`, the direct path below
`2^-4`. Only the correction `sin(a + b + l) - sin a` is computed in double,
from `ups ~ sin b - b` and `cosm1 ~ cos b - 1` (degree 3 minimax polynomials in
`b^2`) and the table: it is under 1.7% of the result, so its roundings cost a
few hundredths of an ulp and the table value and the final addition carry the
precision. `cos` is the same formula with the table's columns exchanged, and
`tan` is `tan a + ((cs - tan a cc) + d0) / (cos_hi + cc)` from the two
corrections, one plain division of a quantity below 3% of the result (odd
quadrants: `cot`, with `e0`). Below `2^-4`, `tan` is a degree 6 polynomial, and
the cotangent of a small remainder a refined reciprocal of a double-double.
Everything is generated by `tools/oracle/fit_kernel.py` at 220 bits and fitted by
Lawson's weighted least squares (a published minimax method).

This replaced a double-double kernel (`r^3/6`, `r^2/2` and `r^4/24` in
double-double, and for `tan` a double-double quotient of the two kernels),
which was correct to 0.50x ulp and cost 24 ns for `sin`, 21 for `cos` and 57
for `tan` at `|x| <= pi/4` (`make bench`, Core 7 150U, GCC 16.2, one core
pinned, loop and call overhead of about 3 ns included). The new kernel takes 8,
9 and 11 ns there, 2.5 to 5 times faster, and 1.6 to 2.7 times faster up to
`2^20`, where the reduction is most of the time. The price is that results are
no longer the nearest double so often: 0.1 to 0.5% differ from the old
kernel's, always by one ulp, and the worst measured error is 0.52 ulp for `sin`
and `cos` and 0.57 for `tan` (`tests/unit/test_trig.cpp`). The accuracy budget is
written in `trig.c`; it is measured, not proved. A vector kernel can be added
later without changing any result: the table row is one cache line and the
formulas are written lane by lane (`kernel_front`, `kernel_tails`,
`kernel_correction`).

**Special values.** `|x| < 2^-28` returns `x` for `sin` and `tan`, and `|x| <
2^-27` returns 1 for `cos`, which is within the contract and is exact for
subnormals and zeros. An infinite or NaN argument gives the quiet NaN
`0x7ff8000000000000` on every target (the sign and payload of the NaN an IEEE
operation makes differs between x86 and the others, so it is fixed), and an
infinity raises invalid.

**Checks.** See the README. The unit test holds the committed corpus to 0.515,
0.521 and 0.535 ulp (sin, cos, tan) as well as to the contract of 1, so that a
wrong table entry is seen; the committed hash catches what even that cannot (one
ulp of a polynomial's low coefficients), `test_trig_kernel.cpp` checks every row
of the table against an independent series, and `check-planted.py` says which
perturbations no test can see and why.


## exp, log and pow

Written from published algorithms and the oracle's results only (Tang, 1989
and 1990; Muller, Elementary Functions, chapters 4 to 7); no library's source
was read. `src/elementary/explog.c`, with the tables and polynomials generated
by `tools/oracle/fit_explog.py` (`explog_tables.h`).

**exp.** `x = n ln2/128 + r`, `|r| <= ln2/256`, and `exp x = 2^(n div 128)
2^((n mod 128)/128) exp r`. `n` is the nearest integer to `x 128/ln2` through the
`2^52 + 2^51` trick (no integer to double conversion). `ln2/128` is split in two
parts, the first of 30 bits so that `n L1` is exact, and `x - n L1` is exact too, so
`r` costs one rounding (`2^-61.5`). `2^(j/128)` is a table of 128 double-doubles
(2 KB) and `exp r - 1 = r + r^2 P(r)` has a degree 3 polynomial fitted to `2^-65`;
`exp x = T_hi + (T_lo + T_hi (r + r^2 P))`, so the only rounding of the size of the
result is the last addition. The scale `2^k` is a bit pattern, exact; above 708
or below -708 it is applied in two steps (and a result in the subnormal range is
rounded twice, within 0.75 ulp). The thresholds (710 and -746) decide infinity
and zero; a result that crosses the overflow or the underflow boundary in between
does so by the multiplication, which raises the exception. `1 + x` is returned below
`2^-54`.

**log.** `x = 2^e m`, `m` in `[0.707, 1.414)` (a bit-pattern offset instead of a
test), cut into 128 rows by the top seven bits of the offset pattern. Row `j`
holds a multiplier `c_j` with 26 significant bits near `1/m`, `t_j = -log c_j` as a
high part that is a multiple of `2^-41` and a low part. Then `z = c m - 1` is
formed exactly in two parts (the high 27 bits of `m` times `c` and the rest
times `c` are exact products, and a FastTwoSum gives `zh + zl`), and `log x =
e ln2_hi + t_hi + [z + z^2 P(z)] + (e ln2_lo + t_lo + zl)`, `P` a degree 5 polynomial
accurate to `2^-60.4` of `z`. The two rows that touch 1.0 have `c = 1` and `t = 0`, so
for `x` near 1 the result is `log1p` of the exact `z = x - 1` and nothing cancels; for
every other row the smallest `|t_hi|` exceeds the largest `|z|`, which `fit_explog.py`
asserts and which is what makes the FastTwoSum of `A` and `z` exact. Measured
0.5048 ulp over the corpus.

**pow.** `exp(y log x)` with the logarithm as a double-double (`log_dd`:
the same rows, `z^2` as the exact sum of two products, a cubic term in double
accurate to `2^-69.5` of `z`, and the `zl (1 - zh)` of the reduced argument's low part; relative error `2^-67`), the product `y log x` as a
double-double (Dekker's product, the halves cut by masking), and `exp_core` taking
`n` from `wh + wl` and `r` from both parts. The error of the logarithm is multiplied
by `|y log x| <= 746`, so the worst results (`x` near 1, `y` huge, a result near
the overflow) are within about 0.51 ulp (measured); an exactly representable result is exact.
The special values follow C99 F.9.4.4, in the order the standard states them, and
are all in the corpus (the specials crossed with the specials) and in
`test_elementary.cpp` row by row. A finite negative `x` uses `|x|` and the parity
of `y`, from the bits of `y` (`integer_class`), so `y` up to and past `2^53` is
right. A `y` of `2^64` or more is decided by the sign of `log x` alone, which
avoids the overflow of the product.

## atan2

`src/elementary/atan2.c`, with the table generated by `tools/oracle/fit_atan2.py`
(`atan2_table.h`). With `u = min(|y|, |x|)`, `v = max`, `q = u/v`, the result is
`B + s atan q`, `(B, s)` being `(0, +)`, `(pi/2, -)`, `(pi, -)` or `(pi/2, +)` by the
signs and the swap, `B` a double-double and the sum a FastTwoSum (the octant
reflections are exact, not a source of error). For `q` in `[1/8, 1]`, `F` is the
nearest multiple of 1/64 and `atan q = atan F + G1 beta + ... + G8 beta^8`, the Taylor
series at `F` (a row of ten doubles, 128 rows so that the masked index is inside the
table), `beta = (u - F v)/v` with `u - F v` formed exactly in two parts. Below `1/8` there
is no table: `q` is a double-double `qh + ql` (the rounded quotient `u (1/v)`, cut to 26
bits, and the exact remainder `u - qh v` times `1/v`; one division in all) and `atan q = q + q^3
P(q^2)`, `P` of degree 6. Below `2^-30` the quotient `u/v` is the result (`q^2/3`
is `2^-61`), and handles every exponent; a `v` outside `[2^-600, 2^600]` is scaled.
Measured 0.5345 ulp over the corpus.

## hypot

`src/elementary/hypot.c`, `hypot_table.h` from `tools/oracle/fit_hypot.py`. No
host `sqrt`: with `a >= b` scaled by a power of two when `a` is outside `[2^-300, 2^300]`, `a^2 +
b^2` is formed as an exact sum of products (`a = ah + al` with `ah` of 26 bits), `1/sqrt`
comes from a 4 KB start (within `2^-10`) and two Newton steps, `c` is the square root with 26 bits
so that `c^2` is exact, and `h = c + (S - c^2)/(c + s0)`, which is `sqrt` to better than `2^-60`.
The result is within 0.5 ulp. If `b < 2^-27 a`, `a` is the result. An infinity beats a
NaN, as C99 F.9.4.3 says. There is no spurious overflow (the scale) or underflow.

## Speed

`make bench` (`tools/bench-trig.c`, `tools/bench-elementary.c`): 4,096 arguments per
range, the best of 200 repeats, the host libm through a volatile pointer, one core
pinned, a warm-up first; each figure includes about 3 ns of loop and call
overhead, the same for both. Core 7 150U, GCC 16.2 in `ghoti-build:gcc16`, `-O2
-ffp-contract=off`, libm of that image, best of five runs; ratios mean something,
absolute figures move with the clock. `gmath` over libm (the story 4 specification has the ns):

| function | common ranges | worst-case range |
|---|---|---|
| `exp` | 0.6 to 0.85 | 0.95 (subnormal results, both pay the microcode assist) |
| `log` | 1.05 to 1.2 | 0.98 (subnormal argument) |
| `pow` | 1.4 (typical), 1.4 (integer exponents), 1.3 (x near 1) | 0.8 (results near overflow and underflow) |
| `atan2` | 0.4 to 0.5 | 1.3 (subnormal arguments) |
| `hypot` | 1.1 (similar magnitude), 1.6 | 1.7 (legs of independent size: the early exit is taken by chance) |

The host's libm may use fused multiply-adds (and a hardware `sqrt`), which this
library may not, so `pow` and `hypot` cost more flops here. As an experiment, `hypot`
with a hardware `sqrt` in place of the table and the two Newton steps measured 1.1
against libm on the host's GCC 14 build (8.4 ns against 7.8) where the shipped
version measures 1.5 there: that difference is what keeping the square root in
`+ - * /` costs, and it was paid on purpose.
